# Translate Projects ReactJs

Automatically translate your React app's [react-i18next](https://react.i18next.com/) locale files into multiple languages, keeping the original JSON structure.

[See documentation](https://translateprojects.neiderruiz.com/docs/frameworks-javascript/reactjs)

## Features

- **Automatic translation**: translates `public/locales/<sourceLang>/*.json` into every target language.
- **Key scanner (optional)**: extracts texts from `t('...')` calls and `<Trans>` components in your source code and builds the base `translation.json` for you.
- **Smart cache**: only changed files and missing keys are sent for translation.
- **Nested JSON support**: nested keys are preserved in the generated files.
- **Typed translations**: `useTypedTranslation` hook autocompletes and type-checks your keys.

## Installation

```bash
npm install translate-projects-react
```

## Usage

### 1. Create a translation script

```js
// translate.js
const { translateProject } = require('translate-projects-react');

translateProject({
  sourceLang: 'en',
  targetLangs: ['es', 'fr', 'pt'],
  apiKey: process.env.TRANSLATE_PROJECTS_API_KEY,
  outputDir: './public/locales', // default
  scanner: true, // optional, scans ./src by default
});
```

```bash
node translate.js
```

`translateProject` resolves to `true` on success. If anything fails (API error, invalid JSON, a language that could not be translated) it prints the real error, resolves to `false` and sets `process.exitCode = 1`, so CI fails without the library killing your process. Target languages are translated in parallel (up to 3 at a time).

### Options

| Option        | Type                               | Default            | Description                                          |
| ------------- | ---------------------------------- | ------------------ | ---------------------------------------------------- |
| `sourceLang`  | `string`                           | —                  | Language of your base files (required).              |
| `targetLangs` | `string[]`                         | —                  | Languages to generate.                               |
| `apiKey`      | `string`                           | —                  | Your Translate Projects API key.                     |
| `outputDir`   | `string`                           | `./public/locales` | Folder with one subfolder per language.              |
| `scanner`     | `boolean \| { sourceDir: string }` | `false`            | Extract keys from source code. `true` scans `./src`. |

### Folder structure

```
public/locales/
├── en/translation.json   ← your source (or generated by the scanner)
├── es/translation.json   ← generated
└── fr/translation.json   ← generated
```

### Scanner

With `scanner` enabled, these patterns are detected in `**/*.{js,jsx,ts,tsx}` and written to `<outputDir>/<sourceLang>/translation.json`:

```jsx
t('Welcome to my app');
<Trans>Hello world</Trans>
<Trans i18nKey="greeting">Hello world</Trans>
```

Very short strings, paths, URLs and template literals with variables are ignored.

### 2. Typed translations (optional)

```tsx
import { useTypedTranslation } from 'translate-projects-react/hooks';
import en from '../public/locales/en/translation.json';

const { t } = useTypedTranslation<typeof en>();

t('home.title'); // ✅ autocompleted
t('home.titel'); // ❌ type error
```

### Utilities

The helpers used internally are exported from `translate-projects-react/utils` (`flattenJson`, `unflattenJson`, `transpile`, …):

```js
const {
  flattenJson,
  unflattenJson,
} = require('translate-projects-react/utils');

const json = { 'v1.0': 'Version 1.0', menu: { home: 'Home' } };
flattenJson(json); // { 'v1.0': 'Version 1.0', 'menu.home': 'Home' }
unflattenJson(flattenJson(json), '.', json); // back to the original shape
```

## How it works

1. Reads the JSON files of `sourceLang` (optionally generated by the scanner).
2. Checks with the Translate Projects API which files changed since the last run.
3. Uploads only the changed content.
4. Requests translations for each target language (reusing cache when keys match).
5. Writes `<outputDir>/<lang>/<file>.json` with the same nested structure.

## Development

```bash
npm install
npm test   # builds, then runs node:test against a local mock API (no AI tokens)
```

The tests need a `translate-projects-core` that supports `TRANSLATE_PROJECTS_API_URL`. Until it is published, link the local core: `ln -sfn ../../core node_modules/translate-projects-core` (run it again after every `npm install`).

One test hits the real backend and spends AI tokens; it only runs when asked:

```bash
REAL_BACKEND=1 TRANSLATE_PROJECTS_API_KEY=... npm test
```
